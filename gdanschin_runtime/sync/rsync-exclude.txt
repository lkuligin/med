# Single source of truth for what never leaves this machine.
# Used by sync.sh for both transfer (--exclude-from) and deletion safety.
#
# The sync runs with --delete, so this list now does double duty: rsync will
# not transfer these paths, AND will not delete them on the remote. That is
# standard rsync behaviour - excluded files on the receiver are protected from
# --delete (only --delete-excluded would remove them, and we never pass it).
#
# Consequence worth knowing: anything the remote creates OUTSIDE these paths
# will be deleted on the next sync, because it does not exist locally. Write
# remote-generated data only into the directories in the first section.
#
# rsync pattern syntax: a leading "/" anchors to the sync root. Directory
# entries below are deliberately unanchored so they match at any depth -
# runs write relative to their working directory, usually llm_monkeys/,
# not the repository root.

# ============================================================
# REMOTE-OWNED. Never transferred, never deleted. Put datasets,
# caches and experiment outputs here and they are safe.
# ============================================================
# datasets and downloaded inputs
data/
# experiment outputs: json, csv, plots
results/
exports/
# model and dataset caches (point HF_HOME here)
cache/
# run logs
logs/
# gpu_serving's state file and server logs, written on the box
gpu_serving/run/
# ad-hoc files made on the remote: debug scripts, notes, patched configs
scratch/
# notebooks written on the GPU box. Excluded so the mirror neither overwrites
# them (a run fills a .ipynb with outputs, the local copy has none) nor deletes
# them. Bring one back with: sync.sh --pull notebooks/
notebooks/

# ============================================================
# LOCAL-ONLY. Internal infrastructure material that must never
# leave this laptop: not committed, not transferred. Unanchored,
# so a supplementary/ at any depth is covered.
# ============================================================
supplementary/
# the remote builds its own against its own CUDA stack. Both serving
# environments are named here: the pattern is a literal directory name, so
# .venv/ does not cover .venv-next/, and an unlisted one would be deleted off
# the box on the next sync for the crime of not existing on this laptop.
.venv/
.venv-next/
venv/
env/
